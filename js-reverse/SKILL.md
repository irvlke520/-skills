# JavaScript 行为分析

先确定用户需要解释的函数、计算或请求参数。网页游戏不是停止代码分析的理由；按钮样式等常规前端任务也不应因游戏名称被转入逆向或安全测试。

## 静态材料优先利用

已有 JS、SourceMap、打包文件或日志时，先核对版本、模块关系和目标函数。逐步理解字符串表、闭包、状态机与数据转换，保留原始位置到整理后代码的对应。

格式化、常量传播与去混淆可能改变求值顺序或副作用；用原始代码和测试输入验证。不要为了读取一个函数默认执行整个脚本或加载远端页面。

## 按需观察

确有浏览器验证需求时，使用环境实际提供的浏览器/MCP能力及其文档。确认页面与脚本版本后，捕获回答问题所需的最少调用证据。不假定 js-reverse_*、固定端口或某个 bootstrap 脚本必然存在。

网络请求、页面操作、读取凭据及发送数据各自依据实际范围执行；离线参数解释不自动升级为认证绕过、请求重放或批量自动化。

## 本地复现

只有用户需要可运行解析/计算时，提取最小相关逻辑，按观察到的依赖补环境。处理时间、随机数、编码、字节序与异步状态，比较输入输出和首个差异点；不通过猜造 window/navigator 属性宣称复现成功。

将本地输出一致与服务端验证通过分开说明。缺少某条链路时继续完成已证据化的部分；本包没有旧文档提到的整套 references 或自动注册脚本，不应因此陷入寻找无关工具。

交付函数解释、数据流、整理后的代码或所需解析器，标注运行情况与未验证的环境条件。
