# 偏移与指针关系恢复

先写清目标字段和证据来源，区分文件偏移、RVA、运行时 VA、实例字段偏移与静态字段存储区偏移。每个偏移绑定样本哈希和 ABI；不复用其它构建的数字作为已验证结果。

## 文件特征扫描

优先使用本技能实际携带的 [scripts/aob_scan.py](scripts/aob_scan.py)，先查看 `--help`。文件模式用 `--file`，`--all` 保留多个命中。模式应包含固定字节；全通配符模式不能识别目标。

扫描结果是候选文件位置。命中后解码指令、核对引用与操作数，不能把“找到一个字节串”写成“定位唯一目标”。重定位字段、相对位移与立即数是否通配，应根据指令语义决定，不依赖固定的最佳模式长度。

## 指针与类型

反汇编中的加法和解引用分开记录。例如以下是符号关系，不是某个游戏的已知偏移：

- 读取模块相对位置得到 manager 指针。
- 从 manager 的已验证字段读取 child 指针。
- 从 child 的字段地址读取目标值。

每一跳都记录读取地址、指针宽度、读取结果、内存区域与失败条件。不要把多次解引用简化成三个偏移连续相加。ASLR 后重新获取模块基址，检查同一解析过程是否仍得到正确对象；不要求绝对地址保持不变。

连续结构数组、指针数组和独立堆对象的遍历方式不同。只有已证实连续存储时，地址差才可支持 stride；一个看似合理的数值或两个相邻地址不足以确认字段类型。

IL2CPP 静态字段存储区与实例字段的基准不同，详见 [engine-internals](../engine-internals/SKILL.md)。

## 验证

通过正常操作制造可控状态变化，对比读取快照、访问指令与生命周期。字段观察不默认写内存；任务确实包含修改时再明确测试对象、预期影响与恢复方法。

根据任务需要选用这些检查：

- 另一次进程运行重新解析模块后仍成立。
- 第二个实例或不同场景支持相同字段解释。
- 对象销毁、容器扩容或转场时，失败可检测并停止使用旧指针。
- AOB 多命中、缺失与版本失配均有明确结果。
- 文件偏移到 RVA 的转换使用目标段映射；内存映像与磁盘文件分别处理。

交付字段名、类型、偏移基准、访问链、构建标识和验证证据。候选位置与可供程序使用的稳定关系分别标记。
