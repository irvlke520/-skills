# 协议 + 三把锁

## 基本形态

- **明文 HTTP（不是 HTTPS）**，端口 80 —— 这是整套方案能成立的前提
- 接口：`http://w<数字>.t3yanzheng.com/<16位hex>`，另有 `w.t3data.net`
- SDK 函数（`AYssu/libSea` 的 `Sea.hpp`）：`T3_LogIn / T3_Update / T3_Notice`
- 加密配置：自定义编码集 Base64 + HEX + MD5 双向签名 + 时间戳校验；密钥与编码集**都在客户端**

## 登录请求（RSA 版本，比 SDK 更严）

```
POST /7865199B50FC57D5 HTTP/1.1
Host: w.t3data.net (103.85.86.98:80，明文)
kami / imei / t / s  各 128 字节 RSA-1024 密文（hex 256 字符）
```
客户端内嵌 RSA-1024 公钥 PEM，`PKCS#1 v1.5 type1` 填充（`00 01 FF×39 00 | 86字节 JSON`）。
响应 chunked，body 标准 base64（172 字符 → 128 字节）。`n`=1024、`e`=65537。

## 响应字段（解密后）

```json
{"code":200,"id":"15424538","end_time":"2026-09-20 13:17:30","amount":"1天",
 "available":74615,"token":"f0da454f...","statecode":"3239f572...","safe_code":null,
 "time":1789806835,"date":"202609191633","imei":"1763-7a70-6440-2312-1213",
 "change":"0","core":""}
```
- `code` 200 成功 / 201 卡密不存在；`available` **恒为正 → 重放时登录判定永远通过**
- `core` 是远程变量下发通道；`imei` 写死 → 共用同一份录制 = 同一设备指纹，有风控风险

## 端点与 IP（会变，动手前重抓）

| 端点 | 用途 | 能否劫持 |
|---|---|---|
| `rules/` `crc/`（走 `japi.*`） | **MRPCS：壳解密主程序** | ❌ 必须直连真实 |
| `/7865199B50FC57D5` | 登录 | ✅ 重放 |
| `/FAD7AD854E8FBBB8` | 公告 | ✅ 重放 |
| `/91B439D4C57AED35` | 心跳，60 秒 | ✅ 重放 |

域名：`japi / w / w2 / w3 / w4 / w5.t3yanzheng.com` + `w.t3data.net`

## 本地缓存文件

| 路径 | 内容 |
|---|---|
| `/sdcard/jngkm55` | **卡密明文 + `\n`**（不是加密的）。存在时启动即自动登录 |
| `/sdcard/.imei` | 设备指纹 |
| `/data/local/tmp/bak_jngkm55` | 某些版本另存一份（**两个都要处理**） |

固定卡密：`printf 'JINLI\n' > /sdcard/jngkm55`

## 三把锁

1. **RSA 签名** —— 不可伪造（无私钥改不了 `end_time`），但**可重放**（客户端只做 `v^e mod n`，分不出新旧）
2. **时间戳** —— 客户端两处比对响应 time 与本地时间，阈值极小；7304/502/93/20/13 秒全失败，≈0 才成功。
   可绕：MRPCS 在启动后 3~4s 做一次、登录在约 7s，中间拨表到 `响应 time - 2` → 报错变成 token 失败（证明锁 2 已过）
3. **token** —— 0 误差对齐仍失败 → token **不依赖时间戳**，绑定请求里的随机熵（RSA 随机填充或 `s` 的随机数）
   → **请求由客户端生成、无法复现，任何重放都过不了，只能改内存**

## 对照实验（同一环境，唯一变量是 patch）

| 组 | patch | 结果 |
|---|---|---|
| A | 无 | `[登录失败] 时间戳校验失败，相差2339秒` |
| C | 仅时间戳 | `[登录失败] token校验失败` |
| B | 时间戳 + token | `[Auto] 登录成功！到期 2026-09-20 13:17:30` |

两处 patch 各自必要 → 反向印证"双锁结构"。

## 静态 patch 也不可行

校验代码在 565KB loader 段（开头 `T-Protector`）：
`token校验@0x17a8c` / `时间戳校验@0x13013` / `登录成功@0x12855` / `RSA公钥PEM@0x14fa6`。
但 45MB 原始文件里这些明文**一个都搜不到**（含 PEM），代码全在 `[anon:.bss]` 匿名映射
→ 静态 patch 的前置是完整脱壳（大工程）。运行时注入入口也全被封 → 只剩 `process_vm_writev`。
