# 函数ID映射表分析

## 1. 映射表概述

T盾 使用函数ID来标识每个加密函数。映射表建立了函数ID与加密函数代码之间的对应关系。

### 1.1 函数ID的作用

- 每个函数有一个唯一的32位函数ID
- Stub 把函数ID保存在栈上，跳转到统一解密器
- 统一解密器根据函数ID查找对应的加密函数代码
- 解密后跳转到解密后的函数执行

### 1.2 映射表可能的位置

映射表可能存储在以下位置：
1. **加密 payload 段的固定偏移**：T盾 加壳时在固定位置写入映射表
2. **统一解密器中的硬编码算法**：不使用表，而是通过算法计算地址
3. **运行时构建**：程序启动时构建映射表到内存
4. **加密存储**：映射表本身也被加密，运行时解密

## 2. 映射表结构推测

### 2.1 可能的结构一：固定大小条目

```c
typedef struct {
    uint32_t func_id;        // 函数ID
    uint32_t encrypted_offset; // 加密代码在 payload 段中的偏移
    uint32_t encrypted_size;  // 加密代码大小
    uint32_t decrypted_size;  // 解密后大小（可能相同）
} MappingEntry;  // 16字节
```

### 2.2 可能的结构二：哈希表

```c
// 函数ID作为键，通过哈希计算索引
typedef struct {
    uint32_t func_id;
    uint32_t code_offset;
    uint32_t code_size;
    uint32_t next_index;  // 链表解决冲突
} HashEntry;
```

### 2.3 可能的结构三：排序数组 + 二分查找

```c
// 按函数ID排序的数组，统一解密器用二分查找
typedef struct {
    uint32_t func_id;
    uint32_t code_offset;
    uint32_t code_size;
} SortedEntry;  // 12字节
```

## 3. 定位映射表的方法

### 3.1 静态分析方法

#### 方法1：从统一解密器逆向

1. 反汇编统一解密器（去混淆后）
2. 找到读取函数ID后的代码
3. 跟踪函数ID的使用：
   - 是否有移位/掩码操作（计算哈希索引）
   - 是否有比较操作（二分查找）
   - 是否有内存读取（查表）
4. 找到基址寄存器，确定映射表地址

#### 方法2：搜索已知函数ID

1. 从入口点 Stub 获取函数ID（如 0xb3062fe8）
2. 在 payload 段中搜索这个函数ID的字节
3. 如果找到，附近可能就是映射表
4. 验证：搜索其他已知函数ID，看是否在同一区域

```bash
# 搜索函数ID 0xb3062fe8（小端：e8 2f 06 b3）
xxd sample.elf | grep "e82f 06b3"
```

#### 方法3：分析高熵段中的低熵区域

1. 计算 payload 段的局部熵
2. 映射表通常是结构化数据，熵比加密代码低
3. 找到低熵区域，分析是否是映射表

### 3.2 动态分析方法

#### 方法1：gdb 内存访问断点

1. 在统一解密器入口下断点
2. 记录函数ID（从栈上读取）
3. 单步执行，观察内存访问
4. 当访问到包含函数ID的内存时，就是映射表

```gdb
break *0x4b7e3c8
commands
    silent
    # 读取函数ID（需要确定栈偏移）
    set $func_id = *(unsigned int*)($sp + 0x??)
    printf "func_id = 0x%x\n", $func_id
    # 设置内存访问断点（需要先知道映射表大致范围）
    continue
end
```

#### 方法2：Frida hook 内存访问（需授权）

```javascript
// hook 统一解密器，记录所有内存读取
Interceptor.attach(ptr("0x4b7e3c8"), {
    onEnter: function(args) {
        this.sp = this.context.sp;
        // 记录函数ID
    },
    onLeave: function(retval) {
        // 此时函数已解密
        // 可以对比解密前后的内存
    }
});
```

## 4. 映射表的验证

找到疑似映射表后，需要验证：

1. **条目大小一致**：每个条目应该有固定大小
2. **函数ID唯一**：每个函数ID应该只出现一次
3. **偏移在有效范围内**：code_offset 应该指向 payload 段内
4. **大小合理**：code_size 应该是正数，且不超过段大小
5. **解密验证**：用映射表中的偏移和大小读取数据，尝试解密，看是否得到有效代码

## 5. 已知样本的映射表情况

对于 T1_904_0414.sh 样本：
- 静态分析未在固定位置找到明确的映射表

  2. 通过算法计算地址（不使用表）
  3. 在统一解密器的 OLLVM 混淆代码中隐藏
- 需要动态分析（gdb 单步跟踪）来确定
