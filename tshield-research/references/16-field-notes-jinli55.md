# 实战笔记：CODM「杰尼龟55」（T盾 1.0.25 + T3，45MB ARM64）

前 15 篇是通用方法论（T1_904 样本）。这篇只记**本项目实测的硬结论**，含几处推翻通用结论的地方。
动手前先读这篇。

## 样本画像

45,470,720 字节，`.sh` 是伪装扩展名，实为 ELF64/AArch64/PIE。
壳横幅 `T-Protector T盾加密保护支持` 在文件 `0x41E19` 与 `0x2731325`（**都在垃圾代码区**，不是代码本体）。
节表只剩 4 个。

## 静态：能确定什么、不能做什么

- **加密区熵满值 8.00**，分组零重复 → 强流密码，**静态不可恢复**，密钥不在文件内
- 全文件 `nop` 44,980 处、`ret` 83 处全在垃圾代码区；函数序言仅 1 处随机命中
  → **文件里没有任何明文可执行代码**
- 唯一有用的明文区是 `0x02AC0000` 起 0.6MB（got/dynsym/dynstr/eh_frame_hdr/dynamic）
- **`.eh_frame_hdr` 能还原 18,851 个函数的布局**（主簇 `0x500000`–`0x0F54D84`）
  → 拿这些地址去 dump 里核对函数开头，是验证 dump 落点最靠谱的方法

**结论：静态解密/静态 patch 在本样本上是死路。**

## 最贵的坑：udf 假阳性

用"有效指令数"判据得到 `valid_insn=2048` 是**假阳性** ——
**AArch64 全零会被 Capstone 判成合法指令 `udf`**，所以全零（未解密）区也能"解出"满屏指令。
改用多点采样（熵 + 分支密度 + 函数序言密度）后唯一命中 **9.33MB**（`base+0x601000~+0xF5C000`，熵 5.7、分支密度 7%）。

**判定解密成功**：正确 dump 的函数开头是 `paciasp / sub sp,sp,#N / stp x29,x30,[sp,#M]`，密文区是乱码。

## 导入表：两级跳转 + 一个误导

```
解密模块 PLT → GOT → 原始 ELF PLT（文件 +0x3C0，107 桩×16B）→ 原始 GOT → libc     （108 桩 / 99 符号）
```
- 解密后**主模块 PLT 里没有 socket/connect/send/recv** → 网络在 **T3 SDK 匿名区**（`0x800000000`，296KB 代码）
- **别被 `.dynstr` 误导**：里面有 `socket/system/popen` 等 148 个符号名，那是**名字残留**，不代表真链接了

→ T3 验证逻辑不在主模块；主模块 9.33MB 解密代码是外挂功能本体。

## 运行时：唯一可靠的不变量

```
扫 maps 的 r-x 段 → 段首 16 字节 == "T-Protector\0" → size == 565248 → 校验 base+0x17a8c 是 "token" 开头
```
- **size 565248 恒定，基址每次都变**（实测 8 个不同值）→ **绝不能写死地址**
- 这个 565KB 段就是校验本体：token校验`@0x17a8c`、时间戳校验`@0x13013`、登录成功`@0x12855`、RSA公钥`@0x14fa6`

## 反调试实测：支点只有一条

| 手段 | 结果 |
|---|---|
| ptrace ATTACH | 挂死 |
| LD_PRELOAD | 空值也杀 |
| frida-gadget | 被检测 |
| 改 hosts | 反篡改检测，直接退出 |
| **`process_vm_writev`** | ✅ **可用，样本无感知** |

**T盾反的是"注入"，不是"改内存"** —— 不 attach、不设 TracerPid、不加载 so、maps 不留痕。
这是绕过方案**唯一的支点**。（改跳转的两处偏移与字节见同级 `t3-kami-bypass` 包）

## 壳解密依赖 MRPCS（和 T3 强耦合）

开局就劫持 → 壳拿不到 rules/crc → **不解主程序** → 没有 565248 段可 patch → `TIMEOUT`
→ 样本 5~12 秒静默退出（日志空）。本地重放 MRPCS 也一样退出。
MRPCS 响应是服务端私钥签名的 RSA 密文，无法伪造 → **完全不联网是机制性不可能**。

## 运维坑

1. 壳异常路径会**死循环占满一核**（曾残留 103% CPU 跑 12 小时，导致用户"所有软件闪退"）
2. **中文进程名 `pgrep` 匹配不到** → 清理必须 `ps -A -o pid,pcpu,comm | grep 杰尼龟`
3. 样本单实例开满功能吃 185% CPU → **排错第一件事是数 `pgrep -x` 的 pid 个数**（2 个必然卡死）

## 走哪条路

| 目的 | 路径 |
|---|---|
| 看懂壳 / 拿解密代码 | 静态分区 + eh_frame_hdr + 运行时 dump（用上面的判据验证落点） |
| 完整脱壳重打包 | 大工程，本项目**没做**（没必要） |
| 改运行时行为（绕验证） | `process_vm_writev` → 见 `t3-kami-bypass` |
| 静态 patch 二进制 | ❌ 明文在文件里搜不到（含 RSA 公钥 PEM） |

`tshield-research`（本包）= 看懂/脱壳；`t3-kami-bypass`（同级）= 不脱壳绕验证。
本样本最终走的是后者。
