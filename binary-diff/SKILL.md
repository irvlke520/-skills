# 跨版本分析与符号迁移

明确旧版、新版与要迁移的名称来源，记录两份输入的哈希、架构和地址基准。游戏更新后的函数名称迁移也是本技能的正常工作；不因应用类别停止。

## 建立候选

用导出、符号、引用字符串、调用关系、常量和控制流寻找对应函数。一个共同字符串或代码相似分数不能单独证明匹配；编译器升级、内联、拆分/合并函数可能改变对应关系。

先处理用户关心的符号。对于虚调用、普通调用、函数指针、全局变量与结构字段，分别记录引用指令位置和目标，不把调用点地址当作被调函数地址。

## 验证对应关系

至少选择能区分候选的语义证据：输入输出、被调函数、分支、字段访问或错误路径。匹配失败保留候选，不强行一一对应；字段偏移跨版本变化后重新验证。

可使用已有 IDA、Ghidra、BinDiff、Diaphora 或命令行工具，不要求特定商业工具。工具版本与实际接口以本机为准。

若用户明确选择外部模型辅助比对，先遵守样本传输和服务使用范围。默认不上传函数、自动注册服务、消耗未授权的 API 额度，也不保证固定费用或准确率。

## 输出与应用

交付旧符号、旧地址、新候选地址、匹配理由、置信情况和需要复核的差异。名称迁移与可执行补丁是两个产物；发现变化不会自动升级成利用实现。

需要写入分析数据库时，对副本应用已核对的名称并保留地址映射。只有请求实施修改时才处理原二进制写入。专项工具说明见 [ida-reverse](../ida-reverse/SKILL.md) 和 [ghidra-reverse](../ghidra-reverse/SKILL.md)。
