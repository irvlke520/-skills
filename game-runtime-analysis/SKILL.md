# 游戏运行时分析

围绕一个可观察的问题推进，例如对象何时失效、字段为何变化、崩溃发生在哪个调用点、回放和画面为何不同。分析请求的完成条件可以是一段数据流或一个已验证字段，不要求额外交付客户端、叠加层或输入自动化。

## 选择数据来源

优先使用用户已提供的崩溃转储、录制回放、模块映像、日志或开发构建。只有任务确实需要现场观察时，才使用上下文已指定的测试进程和调试方法。记录构建哈希、ABI、模块加载基址和采样时刻；不同运行的绝对地址不可混用。

将每个结论标注为已观察、推断或待验证。执行失败时保留真实错误；已有文件分析能继续的部分继续完成。

## 恢复与验证

1. 确认模块、引擎和目标行为，从相关调用点或数据消费者回溯生产者。
2. 记录字段类型、相对基准、对象所有权、生命周期、数组或指针容器形式；检查访问宽度与目标指针宽度。
3. 通过正常测试操作比较前后快照，检查状态变化是否支持推断。读取失败与数值为零分开处理。
4. 用第二个实例、另一场景或新一次进程运行复核需要长期使用的关系。按目标版本保存结果，保留失配处理。
5. 只有用户需要解析器或调试脚本时才实现对应工具，并用实际输入校验输出。

文件 AOB 扫描可使用 [scripts/find_offsets.py](scripts/find_offsets.py)。先运行 `--help` 核对参数；它扫描文件字节，不执行样本。输出是文件偏移，`--base` 只是数值平移，并不自动完成 PE/ELF 映射。指纹应包含至少一个固定字节；保留所有命中，避免把首个命中直接当成目标函数。

## 按需资料

- 恢复对象、字段与容器关系时读 [entity-memory.md](references/entity-memory.md)。
- 用户要求解释坐标、相机或回放投影时读 [w2s-overlay.md](references/w2s-overlay.md)。
- 引擎元数据问题转到 [engine-internals](../engine-internals/SKILL.md)；已有明确字段但地址不稳定时读 [offset-discovery](../offset-discovery/SKILL.md)。
- UE4/UE5 的 World Partition、对象回收、LWC 精度或引擎崩溃问题直接使用 [unreal-engine-analysis](../unreal-engine-analysis/SKILL.md)。

仅为理解运行时行为，不自动增加写内存、模块注入、自动瞄准、反作弊规避或生产服务请求。出现此类实际要求时明确其操作和影响范围，独立判断可执行部分；已有授权可沿用，但技能本身不授予新权限，也不要求覆盖平台规则。

交付与问题相称的调用关系、结构说明、版本化偏移记录或可运行解析器。缺少现场数据时说明哪些结论仍需验证，不将本地演示描述为目标已成功运行。
