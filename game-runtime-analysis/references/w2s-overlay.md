# 相机与坐标投影验证

用于解释已有回放、转储或开发构建中坐标与画面不一致的问题。数学推导所需输入为位置、同一帧的相机变换、投影参数和视口；不把获取其它进程数据视为投影任务的前置步骤。

## 先确定约定

分别记录：

- 行向量或列向量，以及矩阵元素在内存中的排列。
- 左/右手坐标系、相机朝向、近远平面与深度范围。
- 局部、组件、世界、视图、裁剪和归一化设备坐标各自的含义。
- 视口原点、Y 轴方向、宽高与 DPI；避免将物理像素与逻辑像素混用。

采用列向量时，局部点的裁剪坐标为 `clip = P * V * M * point`；世界坐标不再乘 M。行向量约定需要相应顺序。内存转置本身不决定数学约定。

透视除法得到 `ndc = clip.xyz / clip.w` 前，检查输入是否有限、w 是否退化以及目标裁剪约定。w 的符号判断依赖约定，深度不能遗漏；正交投影也不能套用固定透视距离条件。

对于原点在左上角、Y 向下的视口，且 X/Y 的 NDC 范围为 [-1, 1]：

- `screen_x = viewport_x + (ndc_x + 1) * width / 2`
- `screen_y = viewport_y + (1 - ndc_y) * height / 2`

## 选择可解释的检查点

使用相机可见且坐标已知的测试点，分别检查中轴、左/右、上/下、近裁剪面外和后方。世界原点只有恰在相机中轴时才投影到中央；w 不应被断言恒等于 5 或其它固定值。

比较同一帧的引擎投影结果或开发工具截图。出现镜像先查轴方向，旋转错位先查空间与乘法顺序，整幅偏移先查视口/DPI，间歇跳动先查帧同步和数据生命周期。

交付经过核对的约定、公式、测试点与误差。用户只要求解释投影时，完成数学和数据验证即可；额外绘制或运行时操作依据实际请求另行选择。
